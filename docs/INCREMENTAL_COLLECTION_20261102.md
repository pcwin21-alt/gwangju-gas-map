# 온누리 가맹점 분할 수집 운영

## 구현 범위

현재 지역 순서는 **전남 → 전북 → 충남 → 충북 → 경기 → 인천 → 서울 → 강원**이며, 전남의 수집·교차 검증을 마친 뒤 다음 지역으로 넘어간다. 2026-11-02 사용자 지시에 따른 변경이다. 기존 격자 조회 5,083건은 원래 조사 날짜가 있는 참고 자료로 재사용한다. 과거 빈 결과를 현재 비가맹의 증거로 쓰지 않는다. 초기 실행 대기열은 9개이며, 공식 파일 다운로드를 확인하면 후속 요청이 추가된다. 전국 또는 전남 전수조사 완료를 뜻하지 않는다.

GitHub Actions `update-merchants.yml`이 한국시간 00:17 / 03:17 / 06:17 / 09:17 / 12:17 / 15:17 / 18:17 / 21:17에 실행된다. 2026-11-02 사용자 요청으로 6시간에서 3시간 간격으로 변경했다. GitHub의 시작 지연은 가능하다. 노트북이 꺼져 있어도 이 수집기는 실행된다. 전용 `merchant-collector-state` 브랜치에 진행 상황과 원문 응답을 보존한다. 다음 요청 전에 요청 예약을 원격 저장하므로, 중간 종료된 요청도 일일 한도에서 빠지지 않는다. 저장 실패 시 외부 요청을 보내지 않는다.

현재 KB 수집은 시험 단계에서 회차 최대 3회·직전 24시간 최대 24회·요청 간격 최소 180초다. 48시간의 정상 구간과 최근 48시간 내 유효 응답 24개를 모두 충족하면 회차 4회·24시간 32회로 한 번만 증량한다. 공공파일 원천은 24시간 최대 20회를 유지한다. 응답 완료 후부터 대기하고, 응답 완료 시점까지 일일 예산을 차감해 저장·통신 지연도 반영한다. 이것은 자체 제한이며 제공자가 보장한 허용량은 아니다. 명시적 차단을 받은 온누리 API는 초기 상태부터 중단한다. IP 교체, 프록시, 로그인 세션 재사용을 하지 않는다. 과거 직접 실행형 수집기도 관리 수집기를 거치도록 중단했다.

## 반복과 중단 조건

- 정상 응답: 페이지와 원문을 저장한 뒤 다음 작업으로 이동한다. 완료된 작업은 다시 조회하지 않는다.
- 429: `Retry-After`가 있으면 그 시각 이후로 미룬다. 값이 없으면 자동 조회를 멈추고 검토 대상으로 남긴다.
- 명시적 `Request Blocked`, 401, 403: 원천을 영구 중단 상태로 저장한다. 다음 회차나 다른 실행기로 자동 재시도하지 않는다.
- 일시적 서버 오류: 6시간 이상 쉬고 제한적으로 재시도한다. 응답 형식 변경, 페이지 중복, 중간 종료로 응답 여부가 불확실한 요청은 검토 대상으로 남긴다.
- 독립 자료로 차량용 연료 업종·동일 사업장·정확한 가맹점 정체성이 확인되는 지점만 추가한다. 기존 지도 지점을 빈 응답 때문에 삭제하거나 변경하지 않는다. KB 조회는 KB 발급사 확인 범위이며 지류·QR 여부를 추정하지 않는다.

`running`은 남은 작업이 있다는 뜻이다. `needs_attention`은 자동 처리가 끝났어도 신원·주소 또는 원천 자료가 부족하다는 뜻이다. 미해결 자료가 있으면 `complete`로 바꾸지 않는다. 전남 22개 시군의 최신 지정 상권별 입점 목록을 모두 확보하지 못한 범위도 별도 원천 공백으로 유지한다.

현재는 특정 Ralph 플러그인이 아닌 구현 → 검사 → 오류 수정 반복과 재개 가능한 서버 수집기를 사용한다. GitHub Actions는 정해진 수집 코드를 실행하며 새로운 조사 방법을 스스로 작성하는 AI 실행기는 아니다.

## 지역별 완료 후 이동: 2026-11-02 변경

운영 순서의 정본은 `config/collector-policy.json`의 `region_order`다. 사용자가 지정한 앞의 8개 지역 뒤에는 남하하는 기본 순서로 경북 → 대구 → 울산 → 부산 → 경남 → 광주 → 제주를 두었다. 별도 순서를 지정하지 않은 대전·세종은 누락되지 않도록 마지막 후속 권역으로 두었다. 이 후반부 배치는 구현 기본값이며 사용자가 개별 순서까지 확정한 것으로 취급하지 않는다. 중단된 구형 `refresh_regions.py`의 정렬은 운영 수집기에 사용하지 않는다.

앞 지역의 요청 제한·대기 시간에도 뒤 지역을 먼저 조회하지 않는다. 현재 지역의 요청 처리가 모두 끝나고, 미확정 지점·원천 공백이 해소되고, `regional_reviews[지역]`에 `status: complete`, 검토 근거 목록 `evidence`, 확인일 `checked_at`가 남아야 다음 지역으로 넘어간다. 작업이 없는 지역은 조사 완료로 자동 처리하지 않는다. 원천 차단을 만나면 별도 자료 검증을 이어가며, 그 지역을 임의로 완료시켜 건너뛰지 않는다. 공백·검토 항목을 해소했을 때는 근거를 보존하고 `resolved` 또는 `excluded`로 상태를 변경한다. 검증 결과가 0곳이어도 조사 근거와 범위 확인이 필요하다.

입력은 기존 원격 체크포인트·사용자 지정 순서이며, 행동은 정책과 실행 게이트·후속 검토 갱신, 수락 증거는 지역 간 선행 조회 금지·검토 후 전북 우선 이동·서울 다음 강원·기존 요청 이력 보존 검사다. 출력은 서버 실행 코드, 상태 요약의 `active_region`/`regions`, 갱신된 후속 자동화다. 원천별 요청 한도·차단 상태·기존 지도와 사용자 파일은 보존한다.

하네스 라우팅: canonical root AGENTS/Brain은 always, 이 절의 Project 계약과 Project Execution Agent·Toss UX·Global/Software UX Eval은 active다. 실제 인덱스와 파일을 대조했으며 인덱스의 옛 workspace 경로는 발견용 정보로만 취급했다. Style·콘텐츠·발표·새 프로젝트 기획·UI 전면 검토는 이번 순서 변경과 무관해 excluded다. 입력 → 순차 실행 → 정확한 완료/대기 상태라는 사용자 계약만 검사하며 화면 변경은 하지 않는다. 새 개인 메모리 규칙으로 승격하지 않는다.

변경 검증: Python 전체 130개(수집 전용 26개) 검사와 [지역 순서 반영 서버 실행](https://github.com/pcwin21-alt/gwangju-gas-map/actions/runs/41322699244)을 통과했다. 순서 반영 실행은 외부 수집 요청 0회로 기존 응답을 보존했다. 상태의 첫 지역은 전남이며, 전북 이하 지역은 `queued`다. 교차 지역 대기 채우기 금지, 요청 종료와 지역 조사 완료의 구분, 전북 우선 이동, 서울 다음 강원, 미지정/통합 지역 검토 누락 방지, 과거 한도·차단 이력 보존을 검증했다. 화면 코드는 수정하지 않았다.

### 신규 발견을 위한 조사 배분과 입력 보강

사용자의 “전남 갯수 늘릴 방법” 요청에 따라 실제 미발견 가맹 업소를 찾는 데 조사 자원을 배분한다. 원격 요청 이력을 다시 세니 최근 15회가 전부 `post_renewal_recheck`였다. 기존 28곳의 재확인은 필요하지만 그 성공 건수를 신규 발견으로 보고하면 안 된다. 백동산업은 과거부터 같은 전화의 건자재 업소와 업종 충돌이 있었고, 창평가스도 자동차 LPG 여부를 입증하지 못한 오래된 후보다. 이를 매번 새로운 유망 후보로 재소개하거나 같은 조회를 반복하지 않는다.

`config/collector-policy.json`에 `discovery_first_requests_per_run=1`을 두고, 관리 수집기에 활성 지역의 `annual_reverse_discovery` / `full_inventory_identity_followup` 후보 요청 한 회를 우선하는 순서를 추가했다. 후보가 있고 원천·예산·대기 조건이 맞을 때 적용하며 회차 총량을 늘리지 않는다. 현재 pilot 최대 3회라면 신규 후보 1회가 먼저, 나머지는 기존 대기 순서로 진행한다. 기존 지점의 좌표 재확인인 `issuer_coordinate_identity_review`는 신규 발굴 몫으로 분류하지 않는다. 신규 후보가 없으면 기존 작업을 계속한다. 포털의 다운로드 의존 작업 위치와 원격 jobs 순서는 바꾸지 않고, 실제 요청 직전의 선택 순서만 조정한다. 요청 이력·페이지·예약·차단·소스 간격·단계별 한도·전남 우선 순서는 그대로 적용한다.

회차 기록 `last_run.request_purposes`에는 실제 시도한 요청의 목적별 수를 저장한다. 후속 보고는 신규 후보 조회/기존 재확인/신규 지도 반영을 분리한다. “신규 후보 조회 1회”가 “새 주유소 1곳 발견”이라는 뜻이 아니다. Toss UX 원칙은 백엔드의 결과 상태·기대 구분에만 적용하며 지도 UI는 수정하지 않는다.

추가 발굴 입력의 우선순위는 다음과 같다.

1. **전화·실주소가 있는 독립 연료업소 상세명부.** 오피넷 공식 상세정보에는 `TEL`, `NEW_ADR`, `VAN_ADR`, `LPG_YN`, 정유사/충전소 상표, 좌표가 제공된다. 기존 LPG 원자료의 전화 0개 문제를 해소할 가능성이 있다. 인증키가 필요한 공식 API이므로 이용 가능한 정식 연동과 관리 요청 예산을 확인한 뒤 원천으로 추가한다. 이번에 실제 전남 상세명부를 새로 내려받았다는 뜻은 아니다. 공식 근거: https://www.opinet.co.kr/user/custapi/openApiInfoDtl.do?apiId=1 및 https://www.opinet.co.kr/user/custapi/custApiInfo.do . 브랜드 충전소 찾기도 보완 원천으로 검토한다. E1 공식 FAQ에서 충전소 찾기를 안내함은 검색으로 확인했으나 직접 페이지는 타임아웃, SK가스 홈페이지는 읽을 수 있는 내용이 없어 상세명부 확보로 산정하지 않는다.
2. **공식 파일 기준일 이후의 신규 지정상권과 입점 명부.** 2026-07-31 이후 지정·변경 구역을 우선하고, 현재 지도 표시가 없는 전남 시군에서도 독립 연료업소와 교차한다. 지정구역 포함은 온누리 등록과 분리해 기록한다. 상인회 입점 명부에서 법인명·간판명·상세주소를 연결한 후보를 관리 수집기로 확인한다.
3. **KB에 잡히지 않는 결제수단의 원문.** 운영사/소진공의 공개 파일·정식 연계자료 또는 업소가 공개한 실제 사용·가맹 근거를 별도로 검토한다. KB 빈 응답을 지류/QR 불가로 바꾸지 않는다. 영수증·후기는 발견 단서와 거래 시점의 근거로 구분하고 사업장·현재 상태를 다시 확인한다. 기존에 거절된 운영사/LOCALDATA 경로를 다른 IP나 프록시로 재시도하지 않는다.

검증: 후보 1회 후 기존 2회가 이어지는 모의 수집, 포털 작업 위치와 원격 진도 보존, 일일 예산 소진 시 요청 없음, 다음 지역 발굴 작업으로 이동 금지를 포함해 Python 176개가 통과했다. 이번 수정 자체는 외부 원천 요청 0회·신규 지도 추가 0곳이다. 새 명부 보강과 다음 실제 회차의 목적별 실행 결과는 아직 별도 확인 대상이다.
