# 온누리 주유소 지도 모바일 디자인 체계 v1

2026-11-04 KST / 상태: **구성요소·동작 시안 제작, 로컬 브라우저 검수 / 출시 미반영**.

## 목적과 범위

사용자 요청은 적재적소연구소 홈페이지 개편 때 설계한 과정을 담은 스킬에 따라 이 모바일 앱의 디자인 체계와 필요한 구성요소 전체를 제작하는 것이다. 과업은 지역·결제 조건 선택 → 지도·목록 탐색 → 주유소 주소·결제 확인 범위·기준일 확인이다. 메인 화면만 예쁘게 그리는 대신 반복 요소와 상태를 같은 기준으로 만든다.

- 유지: 기존 Sand/Indigo/Jade/Sage 팔레트, 앱 이름·로고, 광주 기본값, 검색·지역·필터·목록·상세, 확인일과 카드사별 근거, 지도 확대·검색 조건 보존.
- 변경안: 한 서체와 두 굵기, 역할별 글자/간격/표면, 두 행의 기본 검색 도구, 공통 팝업 계열, 열린 목록 행, 날짜와 가격의 읽기 순서, 선택 표시와 복구 상태.
- 가정: Pretendard 400/700과 모바일 하단 시트를 이번 시안의 기준으로 채택한다. 사용자가 모든 세부 수치를 확정했다고 기록하지 않는다.
- 현재 범위 밖: 실제 토스 버전 교체·업로드·출시, 공개 지도 수정, 원천 조사 재개, 새로운 위치·행동 수집, 리워드·광고·결제, 토스 내비게이션 자체 제작.

## 적용한 설계 과정

1. `website-visual-direction`: 현행과 이전 확정 사항 확인 → 실제 레퍼런스 → 역할별 기준 → 대표 렌더 → 확장·검수.
2. `codex-delivery-loop/references/visual-component-contract.md`: 표면·컴포넌트 해부·상태·긴 내용·작은 화면의 시각 계약.
3. `toss-ux-principles`: 초기 입력·권한 부담, 맥락 보존, 정직한 결과와 복구. 앱인토스 정책은 일반 UX 원칙과 구분.
4. 공통 `VISUAL_STYLE.md`, KRDS 타이포그래피 기준, `Eval.md`: 16px 본문·상대 행간·충분한 조작 크기·실제 검증 경계.

새 스킬이나 전역 규칙을 만들지 않았다. 이미 정리한 절차를 이 프로젝트의 구성요소와 실제 소스에 적용했다.

계산한 대비: 라이트 본문12.99:1·보조5.83:1·주 행동12.19:1·필드 경계3.50:1, 다크 본문15.15:1·보조8.45:1. 이는 정의한 색 쌍의 계산이며 지도 타일·사진·모든 화면의 접근성 인증이 아니다.

중립 표면을 넓게 두고 Jade를 행동과 선택에 제한한다. 6:3:1 배분은 디자인 출발점으로만 참고하며 지도 타일의 색을 강제로 재색칠하지 않는다. 차분하고 읽기 쉬울 것이라는 디자인 가설이며 색상 자체가 신뢰나 전환을 보장한다고 주장하지 않는다.

토스의 현행 라이트 모드를 유지한다. 다크 시트는 웹 변형과 상태 대비 검토용이며 토스 앱에 테마 토글을 추가한 것이 아니다.

### 타이포그래피와 크기

- Pretendard Regular/Bold 두 파일과 OFL 원문을 로컬에 포함했다. CSS 이름은 `FuelPretendard`, 원본 폰트 바이너리는 수정하지 않았다.
- 읽는 본문·입력16px, 메타14px, 목록 상호18px, 팝업 제목20px, 주요 가격24px. 앱에 장식용 대형 제목을 추가하지 않는다.
- 본문 행간1.6, 제목1.4, 메타1.5. 굵기는400/700 두 역할을 기준으로 한다. 기존 지도 SDK의 타일 글자와 자체 그래픽은 별도다.
- 숫자는 tabular-nums로 비교하고 단위는16px로 구분한다. 가맹 확인일과 유가 기준일은 별도 줄이다.
- 기본 버튼·닫기44px 이상, 검색52px, 내 위치48px. 지도 마커의 실제 크기는24×31px이며 일반 버튼44px 기준의 예외다. 접근 가능한 목록·상세 대체 경로를 유지하며 작은 마커만을 유일한 진입점으로 사용하지 않는다.
- 폰트 두 파일은 합계1,557,048바이트다. 시안의 실제 로드만 확인했으며 새 `.ait`에서 다운로드·시작 성능을 측정하지 않았다. 다음 배포 후보에서 이 비용을 확인해야 한다.

간격은4/8/12/16/20/24/32px 계열을 사용한다. 모바일 안전 여백16px,320px에서는 도구 줄12px로 줄이되 글자와 터치 크기는 유지한다. 지역·필터·보조 메뉴는 모바일 아래 시트, PC에서는 중앙 팝업이다. 주유소 상세는 모바일 아래 시트, PC 우측 패널이다.

일반 목록에 독립 카드 그림자를 반복하지 않는다. 추가 조건(LPG·지류·시군구 등)은 필요한 경우만 도구 아래 줄에 표시하고, 현재 결제수단은 필터 버튼에 표시한다. 결과창이 열려 있을 때 지도 조회 진입점을 중복 노출하지 않는다.

### 정보와 상태

- 제목→주소→결제 확인 범위→가맹 확인일→유가와 기준일 순서다. KB 확인을 지류·QR·운영사 신규 확인으로 바꾸지 않는다.
- 지역·필터 시트는 ESC/닫기와 초점 복귀를 제공한다. 상세를 닫으면 검색·목록·지도 맥락을 유지한다.
- 기본·선택·비활성, 초점, 빈 결과, 지도 실패, 위치 거절, 위치 확인 중, 목록 로딩, 짧은 피드백, 긴 이름/주소를 검토한다. 9개 상태/변형 보드에는 관련 상태를 묶어 표시했다.
- 위치·전송이 없는 갤러리 예시와 실제 지도 동작을 구분한다. 오류 예시를 실제 서버 장애·완료 결과로 표현하지 않는다.
- 시안 문구 정리: ~~저렴한 주유소 TOP5~~ → **가격 낮은 순 · 현재 조건**, ~~왕관·메달 배지~~ → **숫자 순위**, ~~공유 시 서버 확대 약속~~ → **문의 경로 유지**. 순위에 이미 확보된 유가 기준일을 추가 표시했다.

## 구성요소 정본과 구현

32개 요소는 `design/onnuri-fuel-v1/inventory.json`에 ID·계열·계약·데모를 연결했다. 실제 렌더 시트에도 같은 ID를 쓴다.

- 기본3: 글자, 버튼/아이콘, 색/표면.
- 지도9: SDK 내비게이션 경계, 검색, 지역 버튼, 필터/배지, 내 주변/더보기, 결과 범위, 지도 조회, 확대/위치, 마커.
- 지역·필터5: 지역 팝업, 필터 팝업, 결제 선택, 유형/유종/시군구, 초기화/요약.
- 목록5: 결과 시트, 범위/정렬/크기, 결과 행, 추가 보기, 빈 결과.
- 상세5: 상세 시트, 결제 배지, 확인일/출처, 유가 행, 유가 미확인.
- 보조5: 더보기, 가격 순위, 사용 안내, 자료 상태, 언어.

`tokens.css`가 값의 정본, `components.css`가 재사용 요소의 정본이다. `prototype.css`와 `prototype.js`는 고정 인계본 위에 같은 규칙을 적용하는 검토 전용 연결부다. 전역 스타일이 선택 표시를 덮는 문제를 막도록 검토본의 루트 `#fuelDesignApp`에 범위를 한정했다. 기존 소스에 스타일을 계속 덧붙여 배포한 것은 아니다.

생성:

```powershell
python -X utf8 scripts/build_design_review.py
```

기본 출력은 `output/design-system-20261104/site/`다. 공개 배포 폴더에는 생성할 수 없다. 고정 인계본 해시를 검사하며5개 데이터 원문을 바꾸면 실패한다. 갤러리·실제 지도·대표 화면 모음과 라이선스가 함께 생성된다. 원격 출시 파일의 해시를 내려받아 검증한 것은 아니다.

## 실제 검수

- 구성요소32개와 상태/변형9개가 모두 렌더되는 것을 확인했다.
- 실제 CSS 뷰포트320×740,390×844,1280×800. 320px의 root 글자를16→32px로 바꾼200% 모의 글자 조건도 확인했다. 브라우저 Ctrl+/-나 실제 OS 글자 확대 검증이라고 보고하지 않는다.
- 320px/200% 상세·필터,390px 상세·필터,1280px 상세의5조합: 가로 넘침0, 팝업이 화면 안에 위치, 보이는 팝업 버튼44px 미만0. 폰트 로드 확인.
- 전체 갤러리320px/200%/다크: 가로 넘침0, 보이는 예시 입력·버튼·선택44px 미만0. 지역 데모 팝업 안의 가로 넘침0, ESC 닫기 및3px 초점 표시 확인.
- 실제 지도: 검색1곳→결과 행→상세→닫기 시100m/검색어/선택 결과 복귀, 확대 후 클릭·마우스 드래그50m 유지, 지도 조작 시 검색 포커스 없음, 빈 결과→검색어 지우기131곳 복구, 전남28곳→LPG1곳→새로고침 상태 유지.
- 지역·더보기·가격 순위·사용 안내의 실제 기존 동작을 열어 확인했다. 순위 기준일·상세 숫자와 단위·선택 표시도 렌더에서 확인했다.
- 200% 글자에서 상세가 페이지 아래로 밀리는 문제는 viewport 고정으로 보완했다. 긴 유가 문장 안의 기준일이 중간에서 끊기는 문제는 별도 메타 줄로 분리했다.
- JS 두 파일·생성 지도 인라인 스크립트 문법 검사, 정의한8개 색 쌍 대비 검사,5개 데이터 보존 검사 통과. 지도 동작 검사에서 앱 경고·오류 로그0개.

검수 근거는 `output/design-system-20261104/`의 브라우저 캡처와 `browser-verification.json`, `static-verification.json`이다. 정적 갤러리 예시는 서버 연동 증거가 아니며, 실제 지도 시안의 브라우저 조작과 구분했다.

## 다음 적용 경계

현재 결과는 이 앱에 맞춘 디자인 체계와 구현 가능한 검토본이다. 공개 웹·실제 `.ait`·콘솔·수집 자동화는 변경하지 않았다. 사용자 선택 후 실제 앱으로 옮길 때는 기존 CSS 계층을 정리해 토큰을 통합하고, 새 후보의 용량·기기 터치/키보드/SDK 위치/네이티브 복귀를 다시 검증한다. 영문 전체 문구·가로 화면·실기기·추천 지표 실수신은 이번 통과 범위에 포함되지 않는다.

공유 스킬이나 개인 메모리는 변경하지 않았다. 자동 조사 중단 합의도 유지한다.
