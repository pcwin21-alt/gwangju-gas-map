# 모바일 UI/UX 크기·줄바꿈 개선 — 2026-11-02

## 요청 및 실행 계약

사용자 요청: UI/UX를 전반적으로 개선하되, 특히 모바일 글자 크기와 박스 안의 줄바꿈·넘침을 정리한다. 이전 사이드 채팅 요청에 따라 수정 기록은 GitHub 저장소에도 보존한다.

- 과업: 검색·필터 → 지도/목록 → 주유소 상세·길찾기, 경유 창, 더보기와 보조 팝업에서 정보를 읽고 조작한다.
- 입력: 기존 배포본의 실제 화면·계산된 글자 크기, `output/map.html`과 기존 공통 스타일/스크립트.
- 산출물: `assets/responsive-ui.css` 공통 규칙, 경유 창 높이 계산 수정, 번역 맥락 수정, 회귀 시험, 로컬 전용 검수 화면 생성기, 본 기록.
- 수락 조건: 읽는 본문 16px 이상/행간 1.5 이상, 보조 정보 14px, 텍스트 입력 16px 이상, 버튼 높이 44px 이상. 긴 상호·주소와 공백 없는 문자열도 박스 안에서 줄바꿈된다. 320px 폭·200% 글자에서 창의 내용을 스크롤해 읽고 닫을 수 있다. 페이지 가로 넘침과 하단 조작 간 겹침이 없다.
- 범위 밖: 가맹점 조사·데이터 판정·전송·제보 제출·위치 권한 요청·수집 정책 변경. 지도 확대 초기화 및 핀 정보창 안정성 수정은 보존한다.
- 격리 작업: 기존 메인 작업 폴더의 미커밋 소스에 손대지 않고 별도 복제본, `codex/mobile-ux-20261102` 브랜치에서 작업한다.

## 확인된 문제

- 공개본 가격 순위: 주유소명 13px, 주소 11px, 탭 12px/높이 약 33px. 긴 이름과 주소는 한 줄 말줄임이었다.
- 보조 창에는 10~13px 글자와 고정 높이·고정 한 줄 배치가 혼재했다.
- 200% 글자와 매우 긴 상호를 넣으면 상세 제목이 닫기 버튼을 화면 밖으로 밀고, 고정된 제목이 나머지 내용을 덮었다.
- 경유 창은 제목 높이와 상관없이 68px을 빼고 내용 영역을 계산했다. native `details`의 익명 content wrapper 때문에 부모 flex만으로 해결되지 않는 것도 실제 렌더에서 확인했다.
- 작은 화면의 하단 목록·확대 버튼·결과 위치 버튼이 같은 영역을 사용했다. 영문과 큰 글자에서는 겹칠 가능성이 더 커졌다.
- 영문 `경유`는 연료 의미의 Diesel 번역을 공유해, 경유 찾기 입구에도 Diesel로 표시됐다.

## 변경

- 본문·보조 정보·제목·터치 영역을 rem 토큰으로 정의하고 마지막 공통 스타일로 연결했다. 폰트를 무조건 줄이거나 `overflow-x:hidden`으로 문제를 덮지 않는다.
- 좁은 화면의 검색은 한 행을 사용하고 지역/필터 버튼은 다음 행에 놓는다. 긴 버튼 문구와 제목은 높이가 늘어난다.
- 필터·지역·목록·가격·제보·댓글·사용 안내·업데이트·내보내기·후원·경유·상세창을 같은 읽기 기준에 맞췄다. 기존 브랜드와 기능은 유지한다.
- 순위의 가격은 좁은 화면에서 상호/주소 아래로 내려간다. 긴 상호·주소의 말줄임을 해제했다.
- 상세창은 내용별 grid 행을 두고 닫기 버튼이 전체 카드 높이를 기준으로 sticky 동작한다. 긴 제목은 스크롤해 지나갈 수 있고, 아래까지 스크롤해도 닫기 버튼은 보인다.
- 경유 창은 지도 영역과 실제 제목·패딩·테두리를 측정해 내용 높이를 계산한다. 영역/제목 ResizeObserver와 열기 동작에서 갱신한다. 입력·추천 결과·최소화 상태를 초기화하지 않는다.
- 모바일 하단 목록은 확대 버튼과 내 위치 버튼 사이에 놓고, 결과 위치 버튼은 그 위로 분리했다.
- 실제 320px 목록 펼침에서 상단 조건 영역이 202px, 내용창이 249px이어서 첫 결과의 클릭 중심을 가리는 것도 추가 확인했다. 모바일 조건 영역은 목록과 함께 스크롤되게 했으며, 범위·정렬을 두 열로 배치했다. 문구: ~~선택 지역 전체~~ → **선택 지역**, ~~지도에서 찾은 범위~~ → **찾은 범위**, ~~내 위치 가까운 순~~ → **가까운 순**. 선택 지역과 검색 범위에 대한 설명은 목록 본문의 기존 범위 안내에 유지한다.
- 제보 입력에 접근성 이름을 추가했다. 체크박스 자체와 라벨의 터치 영역 크기를 구분했다.
- 영문 경유 입구는 전용 번역 맥락으로 Stops를 표시한다. 연료 선택의 경유는 Diesel을 유지한다.
- 업데이트 안내의 예전 고정 확인 시각을 실제 순차 반영 동작에 맞췄다. 문구 변경: 유가 하루 1회 / 가맹점 ~~매일 오전 6시 30분 확인~~ → **확인된 자료부터 순차 반영**. 영문 경유 입구: ~~Diesel~~ → **Stops**.

## 로컬 렌더 검증

`scripts/build_ui_review.py --output <저장소 밖 임시 폴더>`로 실제 HTML/CSS를 사용하는 검수 화면을 만든다. 지도/자료·전송 스크립트는 제거하며 `_site` 안에는 생성할 수 없다. 실제 경유 창 크기 모듈과 번역 모듈만 실행한다. 긴 상호·주소·영문 연속 문자열·가격은 **검수용 예시**다. 공개 배포에는 포함되지 않는다.

| CSS 화면 크기 | 조건 | 화면 수 |
| --- | --- | ---: |
| 320×740 | 한국어, 기본 글자 | 13 |
| 320×740 | 한국어, root 글자 200%(16→32px) | 13 |
| 390×844 | 한국어, 기본 글자 | 13 |
| 740×360 | 가로 화면 주요 창 | 7 |
| 1280×800 | PC 주요 창 | 6 |
| 320×740 | 영문 주요 창 | 7 |
| 320×740 | 영문+200% 글자+다크 모드 | 5 |
| 합계 | 최종 스타일에서 가로 넘침/44px 미만 버튼 검사 실패 0 | 64 |

검사 대상 13개: 기본 화면, 필터, 지역, 더보기, 업데이트, 가격 순위, 제보, 주변 내보내기, 사용 안내, 댓글/반응, 후원, 경유, 주유소 상세.

측정은 페이지 scrollWidth/clientWidth, 표시된 구성요소의 가로 넘침, 버튼 높이를 사용했다. 텍스트 입력의 본래 한 줄 스크롤과 세로 스크롤은 가로 넘침 실패로 취급하지 않는다. 실제 주유소명·주소를 보이지 않게 잘라 해결하지 않는다.

별도 시각·조작 확인:

- 200% 글자 상세창에서 긴 내용을 끝까지 실제 스크롤해도 닫기 버튼이 카드 안에 남고 하단 경유 버튼에 도달한다.
- 경유 제목이 134px까지 늘어난 조건에서 내용 영역이 실제 높이를 기준으로 줄어들고 세로 스크롤된다.
- 320px 영문 화면에서 하단 목록·지도 맞춤·확대/축소·내 위치 영역의 사각형 교차 0.
- 중간에 발견한 200% 영문 가격 8px 넘침은 단어 줄바꿈 규칙을 보완한 뒤 전체 64개 검사를 다시 통과했다.
- 목록 펼침도 검수 생성기에 추가했다. 320×740에서 기본/200%/영문/영문+200%+다크의 추가 4개 조합 모두 가로 넘침·44px 미만 버튼 0. 최종 고유 배치 조건은 총 68개다. 순위 목록과 주유소 결과 목록은 별도로 구분한다.

이는 브라우저 렌더 및 모의 글자 크기 검증이며, 실제 휴대전화 OS의 글자 확대·키보드·손가락 제스처 검증과 구분한다.

## 후속 수정: 지도 검색 버튼과 목록 메뉴 겹침

사용자 스크린샷과 공개본 728px 화면에서 `이 지역에서 찾기` 버튼이 `주유소 전체 131곳`의 제목을 가리는 문제를 재현했다. 두 요소가 지도 상단에 각각 절대 위치로 놓여 중간 폭에서 충돌했다. 이 후속 작업도 위 최소 하네스 조합과 완료 기준을 적용한다. 입력은 스크린샷·공개 렌더·기존 코드, 행동은 배치 정정, 수락 증거는 두 조작 영역의 비중첩·가로 넘침 없음·지도/목록 상태 보존, 출력은 공통 CSS·HTML 컨테이너·검수 기록이다.

- PC(701px 이상): 두 메뉴를 같은 flex 행에서 배치하고 8px 간격을 둔다. 공간이 부족하면 각 요소 안에서 줄바꿈하며, 왼쪽 지도 크게 보기 버튼의 영역은 비워 둔다. 컨테이너의 빈 공간은 지도 드래그를 막지 않는다.
- 모바일: 검색은 지도 위, 접힌 목록은 지도 아래의 기존 위치를 유지한다. 목록을 펼친 동안 검색 버튼은 화면/탭 순서에서 숨기고, 목록을 접으면 기존 검색 대기 상태 그대로 다시 표시한다. 큰 글자에서 펼친 목록과 검색 버튼이 겹치는 경우도 제거했다.
