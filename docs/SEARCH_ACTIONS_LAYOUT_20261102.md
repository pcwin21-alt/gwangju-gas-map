# 탐색 버튼 위치 조정 — 2026-11-02

사용자 화면에서 `내 주변·가는 길`이 결과 개수 행의 오른쪽에 떠 있고 `내 주변`이 두 줄로 쪼개졌다. 검색/탐색 버튼을 찾고 결과를 확인하는 흐름에 맞춰 위치와 크기만 조정한다.

## 변경 계약

- PC(900px 이상): 검색창·지역·필터 옆 같은 행에 탐색 버튼을 붙인다. 건수·적용 조건은 그 아래에 둔다.
- 모바일: 검색창 바로 아래 왼쪽에 탐색 버튼, 남는 오른쪽 공간에 결과 정보를 둔다. 글자가 커져 부족하면 행 단위로 내려가며 버튼 문구는 한 줄로 보존한다.
- ~~결과 개수 행 오른쪽의 단일 선택 스위치~~ → **검색에 붙은 두 개의 독립 버튼**. 각각 최소 44px, 본문 16px 기준을 사용하고 선택·비활성·키보드 포커스 상태는 유지한다.
- 긴 필터 요약은 한 줄 말줄임으로 표시해 지도를 밀어내는 여러 행을 줄인다. 원문은 접근성 트리에 남고, 상세 조건은 기존 필터 버튼으로 확인할 수 있다. 건수는 줄이지 않는다.
- HTML 내 버튼 ID·이벤트·문구를 유지한다. GPS·경로·키보드·지도 제스처·데이터는 변경하지 않는다. 초기 위치 요청도 추가하지 않는다.

입력은 사용자 첨부/현재 HTML·CSS, 출력은 좁은 DOM/CSS 수정과 검증·배포 기록이다. 완료 조건은 실제 렌더의 버튼 줄바꿈/가로 넘침/겹침 없음, 핵심 기능·검색 맥락 유지, 배포 화면 확인이다.

## 적용 범위

기존 canonical root의 Router/Brain과 본 최소 프로젝트 계약을 always, `toss-ux-principles`·`codex-delivery-loop`를 active로 재사용한다. 두 스킬 전문과 Global/Software UX Gate는 앞선 같은 UI 작업에서 확인한 절차를 적용한다. 코드 탐색·Git·검수 생성기·CUA가 발견/기록/구현/브라우저 검증을 담당한다. 새로운 기획·자료 수집·외부 연동·이미지 생성·서브에이전트는 제외한다. 메인 작업 폴더와 무관한 수집 변경은 건드리지 않는 별도 checkout에서 진행했다. 사용자 최신 AGENTS 지침은 기존 지침보다 우선하며 범위 밖 개선은 추가하지 않는다.

## 로컬 검증

- `node --test tests/search-flow.test.js tests/input-ux.test.js`: 14개 통과. 사이트/검수 페이지 생성과 `git diff --check` 통과.
- 브라우저 32조합: 320×740, 390×844, 740×360, 1280×800 × 기본/200% 글자 × 한국어/영어 × 라이트/다크. 긴 필터 요약을 포함해 가로 넘침·버튼과 상태 영역 겹침·44px 미만 버튼 0건. 두 탐색 버튼의 문구는 모두 nowrap으로 유지했다. 필터 요약만 의도적인 말줄임을 허용했다.
- PC 검색창 옆 배치 및 모바일 검색창 아래 왼쪽 배치를 스크린샷으로 확인했다.
- 제어된 위치 거부 fixture에서 `가는 길 → 목적지 목포역 입력 → 최소화 → 다시 열기`의 입력/선택 상태와 summary 초점 유지 확인. `내 주변` 전환 시 위치 실패 안내와 재시도 활성화, 목적지 유지 확인. 실제 위치/경로 서버는 호출하지 않았다.
- 실제 휴대전화 하드웨어 테스트는 수행하지 않았다. 아주 좁은 화면에서 200% 영문 버튼이 두 행으로 나뉠 수 있으나 단어·버튼 자체는 쪼개지지 않는다.
