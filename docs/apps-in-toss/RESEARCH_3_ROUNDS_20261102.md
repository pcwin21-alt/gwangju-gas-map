# 앱인토스 승인·운영 생존 조건: 3회 조사와 주유소 지도 준비안

확인일: 2026-11-02 KST. 상태: 조사 완료 / 출시 준비안 검토 가능 / 최종 적합성·미니앱 실동작 미확인.

## 결론과 작업 계약

승인, 추천 노출, 지속 운영, 수익성은 서로 다른 결과다. 출시 승인을 받아도 많은 유입이나 수익을 보장받지 않는다. 우리 제품은 **온누리·지역화폐 사용처를 찾고 결제 확인 범위까지 확인하는 과업**에 집중하는 편이 타당하다. 일반 최저가 지도와 경쟁할 때의 차별점이라는 판단이며, 실제 수요·재방문은 아직 검증하지 않았다.

- 입력: 최신 공식 운영·출시·노출 문서, 파트너 인터뷰, 운영자가 공개한 감소 사례, 기존 신청 기록과 두 로컬 소스.
- 행동: 1차 공식 기준 정리 → 부족한 성과 근거를 2차 사례로 보완 → 사례의 편향과 우리 준비물의 차이를 3차 교차 검토.
- 출력: 이 조사·준비안과 별도 출처 목록 `research-sources-20261102.json`.
- 수락 조건: 각 회차의 발견/한계/다음 질문, 근거별 강도, 실제 준비 상태, 우선순위·검증 조건을 구분한다.
- 범위 밖: 계정·토큰 조회, 콘솔 변경·문의 발송·검토 제출, 상품 판매/결제, 광고비 집행, 코드 전환·새 번들 빌드, 가맹점 원천 조회. 기존 파일과 공개 웹사이트를 수정하지 않는다.

여기서 상품은 앱인토스에 올리는 비게임 미니앱을 뜻한다. 상품권 자체를 판매하거나 금융상품을 중개하는 준비안이 아니다.

## 1차: 무엇을 충족해야 승인되는가

### 확인한 기준

**서비스의 허용 범위부터 확인해야 한다.** 현행 서비스 오픈 정책의 ‘출시 불가 서비스’ 9번에는 자동차 관련 카테고리의 한시적 제한이 남아 있다. 주유소 정보 조회가 이 범위에 포함되는지는 우리 앱의 정식 판단 자료가 없다. 앱 생성·사전 입력 확인과 최종 출시 검수는 구분한다. 과거 비슷한 서비스가 존재하거나 다른 카테고리를 선택할 수 있다는 사실은 신규 입점 허용의 근거가 아니다. [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md)

**소개한 기능은 미니앱 안에서 완료돼야 한다.** 외부 링크가 전부 금지되는 것은 아니지만 주요 과업을 외부 사이트·앱에 넘기는 구조는 제한된다. 우리 초기 소개가 정보 조회라면 조회를 안에서 완료해야 하며, 외부 내비게이션까지 가능하다고 쓰려면 해당 동작을 별도로 검증해야 한다. 로그인·결제·광고를 쓸 때도 지정 연동만 허용된다. [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md)

**작동하는 번들과 기기 검증이 필요하다.** 비게임 체크리스트는 플랫폼 내비게이션과 뒤로가기·종료, 필요한 상태 보존, HTTPS, 권한 거절 후 이용, 라이트 테마, 정상 인터랙션 등을 확인한다. 지도는 필요한 확대·축소 제스처의 예외다. 자체 웹사이트를 iframe으로 감싸는 대신 토스 도메인에서 실제 프런트엔드가 동작해야 한다. [비게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-nongame.md)

**등록·검수·출시를 구분해야 한다.** 등록 정보와 번들 준비 후 토스 앱에서 테스트하고 검토를 요청한다. 등록 가이드의 검토 안내는 영업일 3~7일이며 일정 보장은 아니다. 승인 후 출시 동작도 별도다. [미니앱 등록](https://developers-apps-in-toss.toss.im/guide/operation/console-workspace), [토스 앱 테스트](https://developers-apps-in-toss.toss.im/guide/operation/toss.md)

사업자가 없어도 시작할 수 있는 경로는 있으나 모든 기능이 사업자 없이 가능한 것은 아니다. 2026-08-28 인앱 광고 유예는 누적 예상수익 5천 원 미만 범위다. 로그인·결제·프로모션 등의 요건까지 면제한다는 뜻이 아니다. 초기 정보 조회판에 광고·결제는 필수 조건이 아니다. [사업자 등록 유예 안내](https://toss.im/apps-in-toss/blog/update-26-08-27)

### 1차 조사의 부족한 점 → 2차 질문

공식 체크리스트만 보면 ‘돌아가고 금지 기능이 없으면 된다’로 축소하기 쉽다. 출시 후 어떤 앱에 유입이 이어지는지, 누가 실제로 다시 쓰는지, 운영비를 감당하는지는 설명하지 못한다. 따라서 2차는 최신 노출 정책과 실제 운영 사례를 대조했다.

## 2차: 어떤 제품이 계속 이용되고 노출되는가

### 2026-10-22 이후 노출은 세 단계다

| 단계 | 확인되는 조건 | 추가로 얻는 기회 |
| --- | --- | --- |
| 출시 | 내부 검수를 통과한 실제 출시 앱 | 검색·공유 등 기본 진입 |
| 추천 | UX, 실사용 지표, 리뷰, 성능 네 기준 충족 | 스토어·전체탭 추천, 검색 우선 노출 |
| 부스팅 | 같은 카테고리 내 상위 실사용 지표와 에디터 실사용 평가 | 토스 홈·전체탭 상단 추천 공간 |

이는 ‘통과하면 영구 보장’되는 등급이 아니다. 추천·부스팅은 다시 평가된다. 공식 FAQ에는 신규 앱의 맛보기 노출도 안내돼 있으나 개별 앱의 유입량·기간을 보장하는 수치는 없다. 베타의 ‘약 20배’ 노출은 우리 앱의 예상 유입이나 매출 배수로 쓰지 않는다. [노출 기준](https://developers-apps-in-toss.toss.im/guide/exposure), [노출 FAQ](https://toss.im/apps-in-toss/blog/mini-app-exposure-faq)

추천 UX는 첫 기능보다 앞선 로그인·알림 요구를 줄이고, 광고를 예고하며 반복을 피하고, 정보 위계·디자인을 일관되게 하고, 과업 순서·완료 상태를 알리고, 소개한 결과와 의미를 실제로 보여주는 방향이다. 우리 지도에는 ‘조건 선택 → 일치하는 지점 → 결제 범위·확인일 확인’의 연결에 적용한다. [추천 UX 기준](https://developers-apps-in-toss.toss.im/guide/exposure)

재방문과 전환은 카테고리별로 판단하며 공개된 공통 합격률은 없다. 공식 글의 ‘100명 중 30명 재방문’ 같은 수치는 계산 예시다. 리뷰는 별점뿐 아니라 반복 불편 내용도 보고, 성능은 실제 이용을 막는 종료·멈춤 등을 본다. 단순 실행을 전환으로 잡아 지표만 높이는 방식도 평가상 유리하지 않다고 안내한다. [실사용 지표·리뷰·성능 안내](https://toss.im/apps-in-toss/blog/recommended-mini-app-metrics-guide)

광고 수익은 광고 노출 횟수만으로 보장되지 않는다. 공식 설명도 이용 흐름을 방해하는 광고와 광고주의 실제 전환을 구분한다. 초기에 핵심 정보 앞에 광고를 넣기보다 반복 이용을 검증하고, 나중에 광고 전후의 이탈·사용자당 수익·비용을 함께 비교하는 편을 제안한다. [광고 배치와 성과](https://toss.im/apps-in-toss/blog/apps-in-toss-interstitial-ad-guide)

### 2차 조사의 부족한 점 → 3차 질문

- 파트너 스토리는 성공 사례를 선정한 자료다. 실패한 전체 앱 수·관찰 기간·비용이 빠져 있어 성공 확률을 추정할 수 없다.
- 지도 서비스는 매일 쓰는 게임과 이용 주기가 다르다. 어떤 행동을 전환으로 보고 어떤 기간의 재방문을 볼지 정해야 한다.
- 주유소 정보의 정확성·가맹 확인 범위가 나쁘면 화면 완성도만으로 과업을 해결할 수 없다.
- 웹 수정과 토스용 번들 준비가 따로 진행됐다. 실제 제출 후보에 최신 수정이 들어 있는지 확인해야 한다.
- 과거 지원·SDK·홍보 글을 현재 정책으로 오인할 수 있어 상충 내용은 최신 문서로 다시 확인해야 한다.

## 3차: 반론·정책 충돌·실제 준비물 교차 검토

### 보완·정정한 판단

1. **예전 성공을 현재 승인 보장으로 사용하지 않는다.** 자동차 제한은 유지돼 있다. 동시에 기존 앱 생성 기록은 존재한다. 이 둘을 ‘무조건 불가’ 또는 ‘이미 승인’으로 해소하지 않고, 우리 기능·수익 구조를 사실대로 적은 최종 검수의 미확인 사항으로 남긴다. 9월 운영 공지는 개별 미니앱의 사전 적합 판단을 채팅 상담으로 제공하지 않는다고 안내한다. 절차·정책 해석 문의와 공식 검수 결과를 구분해야 한다. [오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md), [9월 점검 공지](https://toss.im/apps-in-toss/blog/update-26-09-10)
2. **노출 자격과 실제 유입의 변동을 구분한다.** 공식 FAQ의 기본 노출 유지 설명과 한 운영자의 유입 감소는 서로 다른 층위다. ‘모든 앱 노출 박탈’이나 ‘유입 감소는 불가능’ 어느 쪽도 입증되지 않는다. 우리 콘솔의 경로별 신규/재방문을 봐야 한다. [공식 FAQ](https://toss.im/apps-in-toss/blog/mini-app-exposure-faq), [운영자 자료](https://fadongkwon.com/ko/posts/toss-exposure-policy-revenue-drop/)
3. **광고성 푸시를 재방문의 기본 수단으로 잡지 않는다.** 스마트 발송의 광고성 푸시·알림은 2026-10-01 종료됐고, 기능성 알림과는 구분된다. 정확한 변화 정보와 명시적 신청 없이 ‘다시 오세요’ 알림을 전제로 설계하지 않는다. [9월 점검 공지](https://toss.im/apps-in-toss/blog/update-26-09-10)
4. **옛 SDK 안내의 도메인을 그대로 쓰지 않는다.** 8월 글의 `web.tossmini.com` 안내와 달리 현행 문서는 SDK 3.1.0 이상에 `apps.tossmini.com` / `private-apps.tossmini.com`을 명시한다. 후보가 선언한 SDK 3.9.0에는 후자의 규칙이 맞는다. 실제 QR Origin·지도 도메인 허용은 여전히 미검증이다. [현행 테스트·Origin 문서](https://developers-apps-in-toss.toss.im/guide/operation/toss.md)
5. **심사 소요 기간을 약속하지 않는다.** 오래된 시작 안내의 2~3영업일과 등록 가이드의 3~7영업일을 구분하고, 현행 등록 가이드의 안내 범위를 준비 일정에 사용한다. 추가 심사·수정 왕복은 별도다. [등록 가이드](https://developers-apps-in-toss.toss.im/guide/operation/console-workspace)
6. **‘메이커 중 매출 발생 비율’을 생존율로 바꾸지 않는다.** 플랫폼 홍보에서 제시하는 매출 발생은 기간별 유지·순이익·노동비 회수와 다르다. 우리 수익은 광고 실측에서 지도/API·데이터 운영·사용자 유입·지원 비용을 뺀 뒤 판단해야 한다. [토스 보도자료](https://toss.im/newsroom/apps-in-toss-10000)

## 우리 제품의 준비 방향

**첫 과업 제안:** 온누리 또는 광주상생카드를 가진 운전자가, 원하는 지역에서 사용처를 좁히고 특정 주유소의 주소·결제 확인 범위·확인일·확보된 가격을 확인한다. GPS 거절 시에도 같은 과업을 지역·주소 검색으로 완료한다. 결제 가능을 보장하거나 모든 전국 가맹점을 갖췄다고 소개하지 않는다.

기존 토스 후보의 정보 조회 범위를 먼저 완성한다. 광고·로그인·후원·경로 비교·외부 내비가 없이도 과업 가치가 있는지 확인한다. 외부 내비가 없어서 실제 이용 가치가 부족하다는 사용자 반응이 반복되면, 허용 여부·복귀 동작·개인정보 전송을 검증한 다음 확장한다. 이 초기 범위는 기존 공개 웹의 기능 삭제 요청이 아니다.

### 우선순위와 통과 증거

| 순서 | 준비 과제 | 다음 단계로 갈 증거 |
| --- | --- | --- |
| P0 | 카테고리 제한과 제출 설명 정합성 정리 | 자동차 관련 정보 조회임을 숨기지 않은 소개·실제 기능 목록·최종 심사 미확인 표시. 별도 상담 결과가 있다면 원문 보존 |
| P0 | 최신 웹 수정·데이터 정정을 토스 후보에 병합 | 공통 화면·임베디드 데이터 대조, 빌드 및 실제 토스용 렌더 회귀 검사. 기존 플랫폼 제외 항목 재유입 없음 |
| P0 | Origin·지도·위치·뒤로가기 검증 | 실제 QR 버전의 Android/iOS 증거, 위치 거절 후 수동 검색, 지도·목록 왕복 시 필터/확대/입력 유지 |
| P0 | 소개·로고·문의·권리·데이터 흐름 확인 | 실제 수신 가능한 고객문의, 공식 운영 앱으로 오인시키지 않는 표현, 지도/상가/가맹/가격 자료의 이용 조건 확인, 위치·식별키·외부 수신처와 보관 범위에 맞는 고지 |
| P1 | 핵심 행동·오류 측정과 콘솔 지표 설정 | 실제 이벤트 수신·중복 방지·대표 전환 설정. 샌드박스 데이터를 운영 지표로 사용하지 않음 |
| P1 | 적절한 범위에서 초기 이용 관찰 | 어디서 왔는지, 결과를 얻었는지, 다시 필요한 날 돌아오는지, 실패 이유가 무엇인지의 분모 있는 기록 |

P0는 내부 준비 우선순위이며 토스 공식 심사 등급이 아니다. 카테고리 판단은 미니앱 검수 결과가 필요할 수 있으므로, 채널톡의 사전 승인 약속을 기다리는 절차로 고정하지 않는다. 준비·테스트를 마쳐 검토를 요청하는 데 필요한 사용자 확인은 기존 콘솔 절차를 따른다.

### 전환·재방문 설계 초안 — 아직 구현/등록하지 않음

대표 전환 후보는 **조건에 맞는 주유소의 결제 정보 확인**이다. 단순 앱 실행·지도 자동 노출과 분리한다. 사용자가 지점을 직접 선택했고, 유효한 일치 결과의 주소·결제 확인 범위·확인일이 실제 화면에 나타난 경우를 이벤트 `qualified_station_info_view`로 정의하는 안이다. 세션 내 중복은 제거한다. 이는 정보 조회 가치의 대리지표이며 실제 방문·주유·결제나 현장 사용 가능을 증명하지 않는다. 체류시간 몇 초를 넣어 전환을 부풀리지 않는다.

- 보조 분석: `station_search_result`(결과 있음/없음), `station_detail_open`, `location_result`(허용/거절/실패), `map_load_failure`. 지도 SDK 실패의 주소 목록 복구도 별도 구분한다.
- 수집 제안: 넓은 지역, 결제수단 종류, 결과 유무, 오류 종류처럼 과업 분석에 필요한 값만. GPS 원좌표·자유 입력 검색어·개인 식별 원문은 분석 이벤트에 넣지 않는다. 실제 SDK가 자동 수집하는 항목도 별도 확인한다.
- 콘솔은 활성 지표 1개, 전환 지표 최대 3개와 대표 전환 1개를 지원한다. 위 이벤트명이 곧바로 사용 가능한 API/콘솔 설정이라는 뜻은 아니며 SDK 로그와 실제 콘솔 이벤트를 맞춰야 한다. [핵심 지표 설정](https://developers-apps-in-toss.toss.im/guide/analytics/conversion-metrics)
- 로깅 문서는 실제 출시 이후 데이터와 다음 날 분석 화면을 안내한다. 시험 데이터가 대시보드에 안 보이는 것을 곧바로 구현 실패로 판정하지 않는다. [이벤트 가이드](https://developers-apps-in-toss.toss.im/guide/analytics/logging)

내부 관찰안은 최초 사용 후 4~8주 동안 정보 확인 완료율, 28일 내 재확인, 데이터 오인/빈 결과·지도 실패 사유, 유입 경로별 신규·재방문을 함께 보는 것이다. 이 기간은 주유 이용 주기를 검증하기 위한 제안이며, 공식 추천 평가 기간이나 승인 기준이 아니다. D1·D7도 참고할 수 있지만 매일 접속을 유도하는 것이 제품 목표는 아니다.

초기 관찰 대상 수나 목표 전환율을 현재 근거 없이 합격선으로 정하지 않는다. 기여 지역·결제수단·유입 경로·관찰 완료 여부를 나누고 분모를 기록한다. 이용자 수가 적으면 정성 피드백과 과업 재현을 먼저 보며, 수치 차이를 성급히 통계적 개선으로 표현하지 않는다.

## 3회 조사로도 남은 미확인

- 우리 앱의 최종 카테고리 적합성·심사 결과와 실제 토스 앱 동작.
- 개별 제품의 공개되지 않은 추천 임계값·가중치, 편집 선정 가능성.
- 성공 사례의 장기 유지율·순이익·전체 실패 분모. 소개 기사는 승인률·생존율의 표본이 아니다.
- 실제 지도/API·데이터 이용 권한, 운영 비용과 수익. 현재 가격표·계약·계정 설정을 확인한 것으로 보지 않는다.
- 우리 사용자의 반복 이용 수요. 현행 웹 브라우저 QA는 앱인토스 제품 수요의 증거가 아니다.
