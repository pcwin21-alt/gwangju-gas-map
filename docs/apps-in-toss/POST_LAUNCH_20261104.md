## 가장 먼저 다룰 데이터 갱신 문제

비교 대상은 로컬에 보관된 고정 인계본 SHA-256 `e1f72f65b654b4b5bc2bc7430261c5614a824697d4c85d91a8dc0b85faf63c7f`와 현재 저장소의 `output/map.html`이다. 버전명은 출시 콘솔과 일치하지만 원격 출시 파일을 다운로드해 같은 해시인지 검증한 것은 아니다.

| 항목 | 고정 인계본 | 현재 웹 소스 |
| --- | --- | --- |
| 전체 등록 기록 | 220 | 220 |
| 온누리 태그 기록 | 184 | 184 |
| 가격 데이터가 있는 지점 | 25 | 27 |
| 확보된 유가의 가장 최근 기준일 | 2026-11-02 | 2026-11-03 |

두 소스의 `STATIONS`, `PRICES`, `PRICE_INFO`, `MERCHANT_STATUS`는 다르다. 기록 수가 같은 것이 확인 근거·기준일까지 같은 뜻은 아니다. 이 비교로 새로운 주유소를 발견하거나 가맹 상태를 재확인한 것은 아니다.

현재는 자료를 `.ait` 안에 넣으므로 웹이 갱신돼도 토스 버전은 계속 고정 자료를 보여준다. 다음 수정은 **이미 확보된 자료로 새 후보를 만들고 데이터 기준일을 검증하는 것**부터 시작한다. 지속 운영은 별도로 공개 데이터 버전·형식 검증, 실패 시 검증된 내장 자료 복귀, 확인일 보존을 갖춘 읽기 전용 갱신 방식을 설계한다. 이 설계나 이번 점검은 중단한 가맹점 조사의 재개를 뜻하지 않는다.

## 전환 측정 설계 — 아직 코드·콘솔에 적용하지 않음

구매·예약이 없는 정보 지도다. 대표 전환 후보는 **주유소 상세 정보 확인**이다. 지도 클릭 횟수나 앱 열기를 주유·결제 완료로 부르지 않는다.

| 제안 이벤트 | 발생 조건 | 목적 |
| --- | --- | --- |
| `fuel_station_detail_view` | 실제 상세가 열리고 주소·결제 확인 범위가 렌더된 뒤. 지도·목록·지도 실패 시 상세를 같은 기준으로 처리 | 대표 전환 후보 |
| `fuel_search_results` | 사용자가 검색을 끝내 결과가 반영된 뒤. 키 입력마다 보내지 않음 | 빈 결과·검색 이탈 진단 |
| `fuel_map_error` | 지도 표시 실패 후 대체 목록이 제공되는 경우 | 핵심 실패 경로 진단 |

첫 적용은 상세 성공 이벤트 하나로 최소화한다. 전달 값은 `surface=map/list/fallback` 같은 제한된 분류만 검토하며 검색어·상세 주소·좌표·전화·로컬 식별키·원문 오류를 추가하지 않는다. [공식 Analytics.log](https://developers-apps-in-toss.toss.im/documentation/sdk/domains-api/analytics/analytics.log)는 SDK가 `anonymous_key`를 자동 포함한다고 명시하므로 이를 식별 정보가 전혀 없는 집계로 설명하지 않는다. 실제 전송 범위와 이용자 고지를 확인한 뒤 적용한다.

다음 검증 순서: 성공·실패·중복 열기 구분 검사 → 새 후보 브라우저/토스 테스트 → 출시 버전과 이벤트 실수신 확인 → [콘솔 핵심 지표](https://developers-apps-in-toss.toss.im/guide/analytics/conversion-metrics)에 대표 전환 등록. 숫자만 채우려고 수익·로그인 템플릿을 선택하지 않는다. 재방문은 주유 이용 주기에 맞춰7일·30일 관찰을 비교하고, 초기 표본 없이 성과 목표나 활성 기준을 확정하지 않는다.
