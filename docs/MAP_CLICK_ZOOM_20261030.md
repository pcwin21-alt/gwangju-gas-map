# 지도 클릭 후 줌 초기화 수정

요청 및 최소 계약: 확대·이동 후 일반 지도 클릭 시 확대 수준과 중심, 주유소 필터가 유지되어야 한다. 기존 구 경계와 구 이름 표시는 유지하고 명시적인 지역 필터·결과 보기 기능은 계속 작동한다. 입력은 공개 지도 소스와 사용자의 오류 보고, 출력은 수정된 공개 사이트와 재현 검사다.

원인: 광주 5개 구의 반투명 폴리곤 클릭이 `triggerDistrictSelect`를 실행했고, 필터 적용 후 `mapViewport.fit()`으로 중심·줌을 변경했다. 실제 수정 전 브라우저에서 50m 축척이 한 번 클릭 후 100m로 돌아가는 현상을 재현했다.

수정: 폴리곤의 클릭 필터 이벤트를 제거한다. 지도 클릭은 지도를 보는 동작으로 유지하며, 구 필터는 필터 메뉴에서 명시적으로 선택한다. 구 경계·구 이름·지도 중심 안내를 계속 표시한다. 별도 라이브러리나 API는 추가하지 않는다.

검증 계획: 기존 실제 HTML의 구 경계 생성 및 메뉴 이벤트를 실행하는 회귀 검사로 클릭 시 줌·중심·필터 불변과 메뉴 선택 시 정상 필터/보기 맞춤을 확인한다. 첫 검사는 수정 전 실패를 확인했다. 전체 검사, 사이트 빌드, 배포 후 공개 브라우저에서 동일 클릭을 재검증한다.

완료 증거: Node 57개 및 Python 100개 검사 통과, `prepare_site.py` 빌드 및 diff 공백 검사 통과. 기능 커밋 `7855738`, 배포 40998330446 및 Pages 40998345115 성공. 공개 브라우저 728×831에서 돌고개주유소 검색 후 50m로 확대한 뒤 같은 지도 좌표 (180,410)를 클릭했다. 클릭 전후 축척 50m, 필터 all, 결과 1곳이 유지됐고 타일 32개의 URL/배치 및 구 이름 위치가 동일했다. 메뉴의 서구 선택도 정상 적용됐으며 테스트 후 전체 구로 복구했다. 화면 증빙은 Playground/output/onnuri-zoom-click-fixed-20261030.jpg. 실제 휴대전화 터치 검증은 별도로 수행하지 않았다. 수락 조건 및 Eval Global Gate 통과.

## 모바일 후속 점검

390×844 브라우저 화면에서 50m 확대 후 단일 클릭 시 타일 배치·필터·축척이 유지됐다. 드래그 시 타일이 이동하면서 축척 50m가 유지됐고, 경유창 바깥 지도 클릭으로 창을 최소화해도 지도가 그대로였다. 다만 360×780으로 화면 폭을 바꾸자 기존 ResizeObserver의 자동 fit이 100m로 초기화했다. 크기 변경 시에는 지도 그리기 영역과 현재 중심만 갱신하고 자동 fit은 실행하지 않도록 수정한다. 초기 로딩·명시적인 검색/필터 변경·결과 보기의 fit은 유지한다.

검증 경계: 제공된 브라우저 도구의 모바일 화면 크기 설정과 마우스 입력으로 점검한다. 실제 Android/iOS 터치와 두 손가락 핀치는 직접 실행할 수 없어 검증 완료로 표시하지 않는다. 앱의 touchstart/pointerdown 처리는 기존 자동 검사로 별도 확인한다.

후속 완료: 커밋 `34ad8b9`, 검사 40998849958/40998849584 및 배포 40998849995/Pages 40998862906 성공. Node 57개/Python 100개 통과와 사이트 빌드 확인. 공개 사이트에서 360×780 클릭 전후 타일·필터 불변 및 드래그에 의한 타일 이동을 확인했다. 320×740에서도 클릭 불변 및 드래그 이동을 확인했고 타일 확대 수준 3을 유지했다. 844×390 가로 화면 전환 후 390×844 세로 복귀 시에도 타일 확대 수준 3과 50m 축척, 결과 1곳/전체 구 필터를 유지했다. 390×844에서 경유창 바깥 지도 클릭에 의한 최소화도 화면을 변경하지 않았다. 증빙: Playground/output/onnuri-mobile-zoom-checked-20261030.jpg. 임시 화면 크기는 원래대로 해제했다. 실제 모바일 터치 및 핀치 미검증을 포함한 증거 경계를 유지하며 이번 브라우저 점검의 수락 조건은 통과했다.
