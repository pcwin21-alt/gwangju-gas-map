## 데이터와 갱신

- 정본: `assets/onnuri-policy.json`. 발표일, 시행일, 종료일, 추진 상태, 기본 구매할인, 공식 출처와 실제 확인일을 별도 필드로 관리한다.
- `scripts/build_policy_data.py`: 출처·날짜·추진 상태를 검사하고 `assets/onnuri-policy-data.js`를 생성한다. 웹과 토스 빌드는 같은 검사를 거친다.
- `assets/onnuri-policy-core.js`: 한국 날짜로 시작 전·기간 한정·기간 종료를 구분한다. 추진안은 날짜만으로 시행 중이 되지 않는다.
- 향후 기본 구매할인 변경의 정확한 시행일이 공식 확정되면 해당 공지에 `kind=confirmed`, `affects=digital_base`, `rate`, `startsOn`을 기록한다. 검증된 확인 기간 안에서만 한국 날짜의 시작일에 새 기본값을 적용한다. 소비환급·총혜택·한시 특별판매를 이 필드로 넣지 않는다. 현재 2027년 추진안에는 이 필드를 적용하지 않았다.
- 공식 확인 후 7일을 넘기거나 확인일이 미래이면 현재 할인 숫자를 숨기고 `온누리 혜택·정책`으로 표시한다. `recheckBy`는 연말 재점검을 강제하는 표시 기준이며 실제 정책 종료일을 주장하는 필드가 아니다.
- 웹은 같은 사이트의 JSON, 토스 후보는 `https://pcwin21-alt.github.io/gwangju-gas-map/assets/onnuri-policy.json`을 시작 시 1회 읽는다. `새로 확인`은 이 게시 자료를 다시 읽는 행동이며 정부 원천을 실시간 조사했다는 뜻이 아니다.
- 네트워크 실패·잘못된 형식·더 오래되거나 미래인 확인일이면 내장 확인 자료를 유지하고 상태를 표시한다. HTML 문자열을 실행하지 않으며 출처는 허용한 HTTPS 호스트만 사용한다. 요청에 위치·검색어·식별키·자격증명·리퍼러를 넣지 않는다.
- 매일 한국시간 오전9시 자동 점검(`automation-7`, 온누리 정책·할인 변동 점검)을 설정했다. 새 공식 공지·정정·시행일을 확인하고 검증된 정책 정보만 갱신·검사·웹 배포·재확인한다. 기존 가맹점 발굴 방법 검토(`automation-5`)와 별개이며 중단한 원천 수집을 재개하지 않는다. 자동화 실행 전에도 날짜가 지난 행사는 화면에서 종료로 분류한다.
